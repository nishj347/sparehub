# SpareHub - Disaster Recovery & Restore Runbook

This guide covers restoring a SpareHub database and media uploads archive from backups generated by `scripts/backup.sh` (or `scripts/backup.ps1`).

---

## 1. Prerequisites

- A running SpareHub production stack (`docker compose -f docker-compose.prod.yml ps`).
- A valid PostgreSQL dump file (`backups/sparehub_db_YYYYMMDD_HHMMSS.dump`).
- A valid uploads archive (`backups/sparehub_uploads_YYYYMMDD_HHMMSS.tar.gz`).

---

## 2. Dry-Run Verification (Testing Restore into a Scratch Database)

Before restoring directly into production, **always** test the dump into a separate temporary database inside the running `db` container to ensure the dump is intact and uncorrupted.

### Step 2.1: Copy dump file into container
```bash
docker cp backups/sparehub_db_20261101_070000.dump sparehub_prod_db:/tmp/restore_test.dump
```

### Step 2.2: Create a scratch database
```bash
docker exec -it sparehub_prod_db sh -c "psql -U \"\$POSTGRES_USER\" -c 'DROP DATABASE IF EXISTS sparehub_restore_test; CREATE DATABASE sparehub_restore_test;'"
```

### Step 2.3: Restore dump into scratch database
```bash
docker exec -it sparehub_prod_db sh -c "pg_restore -U \"\$POSTGRES_USER\" -d sparehub_restore_test --no-owner --role=\"\$POSTGRES_USER\" /tmp/restore_test.dump"
```
*(Note: `pg_restore` returns code 0 or exits cleanly with schema and data restored).*

### Step 2.4: Verify table counts in scratch database
```bash
docker exec -it sparehub_prod_db sh -c "psql -U \"\$POSTGRES_USER\" -d sparehub_restore_test -c \"
SELECT 'users' AS table_name, count(*) FROM users
UNION ALL SELECT 'spare_parts', count(*) FROM spare_parts
UNION ALL SELECT 'inventory', count(*) FROM inventory
UNION ALL SELECT 'inventory_transactions', count(*) FROM inventory_transactions
UNION ALL SELECT 'notifications', count(*) FROM notifications;\""
```

### Step 2.5: Clean up scratch database and temporary file
```bash
docker exec -it sparehub_prod_db sh -c "psql -U \"\$POSTGRES_USER\" -c 'DROP DATABASE sparehub_restore_test;'"
docker exec -it sparehub_prod_db rm -f /tmp/restore_test.dump
```

## 3. Full Production Disaster Recovery Restore

> [!WARNING]
> This procedure will overwrite all live data in the active production database! Ensure any active users have been notified or stop the backend service first.

### Step 3.1: Stop traffic to backend
```bash
docker compose -f docker-compose.prod.yml stop backend web
```

### Step 3.2: Copy files to container
```bash
docker cp backups/sparehub_db_20261101_070000.dump sparehub_prod_db:/tmp/restore_prod.dump
```

### Step 3.3: Drop and recreate live database
```bash
docker exec -it sparehub_prod_db sh -c "
psql -U \"\$POSTGRES_USER\" -d postgres -c \"
  SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = '\$POSTGRES_DB' AND pid <> pg_backend_pid();
  DROP DATABASE IF EXISTS \\\"\$POSTGRES_DB\\\";
  CREATE DATABASE \\\"\$POSTGRES_DB\\\" OWNER \\\"\$POSTGRES_USER\\\";
\""
```

### Step 3.4: Restore dump into live database
```bash
docker exec -it sparehub_prod_db sh -c "pg_restore -U \"\$POSTGRES_USER\" -d \"\$POSTGRES_DB\" --no-owner --role=\"\$POSTGRES_USER\" /tmp/restore_prod.dump"
docker exec -it sparehub_prod_db rm -f /tmp/restore_prod.dump
```

### Step 3.5: Restore media uploads archive
```bash
docker cp backups/sparehub_uploads_20261101_070000.tar.gz sparehub_prod_backend:/tmp/uploads_restore.tar.gz
docker exec -it sparehub_prod_backend sh -c "tar -xzf /tmp/uploads_restore.tar.gz -C /app && rm -f /tmp/uploads_restore.tar.gz"
```

### Step 3.6: Restart services and verify health
```bash
docker compose -f docker-compose.prod.yml up -d backend web
docker compose -f docker-compose.prod.yml ps
curl -fsS http://localhost:8080/api/health/db
```

## 4. Automated Backup Scheduling

Backups should be executed daily with a 14-day retention cycle.

### Linux / macOS Cron Job
Edit crontab with `crontab -e`:
```cron
# Run SpareHub backup daily at 02:00 AM UTC
0 2 * * * cd /opt/sparehub && ./scripts/backup.sh >> /var/log/sparehub_backup.log 2>&1
```

### Windows Task Scheduler (PowerShell)
Open PowerShell as Administrator:
```powershell
$Action = New-ScheduledTaskAction -Execute 'PowerShell.exe' `
  -Argument '-NoProfile -ExecutionPolicy Bypass -File C:\sparehub\scripts\backup.ps1'
$Trigger = New-ScheduledTaskTrigger -Daily -At 2:00AM
Register-ScheduledTask -Action $Action -Trigger $Trigger -TaskName "SpareHubDailyBackup" -Description "Daily PostgreSQL & Uploads backup"
```
